## Контекст

В репозитории лежит набор AppleScript-сценариев для автоматизации **GoPro Player** на macOS. Активная ветка — `cursor/applescript-gopro-player-d935`, открыт PR #2.

Целевой workflow пользователя:
- На внешнем диске `/Volumes/NINJAV/cloude - timati/Riv/` (и аналогичных) лежит иерархия вида `RIV_<date>_<id>_<email>/[gopro1|gopro2|N]/GS0XXXXX.360`.
- Нужно: рекурсивно найти все `.360`, **по одному** прогнать через GoPro Player, экспортировать в `.mp4` **в ту же папку, где лежит исходник**, дождаться завершения рендера, удалить исходный `.360` (по умолчанию в Корзину), перейти к следующему.
- macOS на русском, GoPro Player с диалогом «Настройки экспорта» (radio-кнопки `Разрешение`/`Кодек`, чекбоксы `Блокировка направления`, `Линия горизонта`, `AntiShake`, `Оптимизация крепления`, ползунки `Скорость экспорта`, `Качество`, `Размер файла`, `Битрейт`, `Denoise`, кнопки `Отмена` / `Отправить в очередь` / `Далее…`).

Главный файл: `scripts/gopro_render_then_delete_360.applescript`.

## Текущее состояние

- Скрипт собирается через `osacompile -o "GoPro 360 Render.app" …` и работает как droplet.
- Карантин снимается через `xattr -dr com.apple.quarantine`.
- Права в `Универсальный доступ` и `Автоматизация` выданы пользователем (`-25211` и `-1708` уже починены).
- `.360` файлы скрипт находит корректно (в последнем прогоне нашлось 6 штук).
- Скрипт корректно открывает каждый `.360` в GoPro Player.

## Проблема, на которой остановились

**Рендеринг не запускается.** При запуске .app:

1. Открывается GoPro Player с первым клипом (видно глазами).
2. Скрипт пытается вызвать `Файл → Экспорт…`, но диалог «Настройки экспорта» не появляется.
3. После таймаута (60 сек) возвращается ошибка `-2700 «Не дождался диалога Настройки экспорта»`. Так для всех 6 файлов подряд.

Я уже добавил `waitForExportEnabled()` (поллинг свойства `enabled of menu item "Экспорт…"`) и ретраи `kExportRetries = 3`, но судя по последнему сообщению пользователя — всё равно «просто открывает программу, рендеринг не начинается». То есть либо пункт меню остаётся серым дольше 120 сек, либо клик по нему не открывает sheet. Возможные причины:

- Пункт `Экспорт…` в этой версии GoPro Player называется не `Экспорт…`, а как-то ещё (например, `Экспортировать…`, `Экспорт видео…`, `Сохранить как…`).
- Команда `click menu item …` через `System Events` срабатывает, но GoPro Player проглатывает клик из-за внутреннего state — известная проблема некоторых App Store приложений с песочницей.
- На этом томе clip не проходит индексацию stitching — GoPro Player «висит» в загрузке, и `Экспорт…` остаётся неактивным навсегда.

## Что нужно сделать

### 1. Диагностика реального меню GoPro Player

Сделай вспомогательный скрипт `scripts/gopro_dump_menu.applescript`, который активирует GoPro Player и через `System Events` выгружает в файл (`/tmp/gopro_menu_dump.txt`) полный список:
- всех `menu` в `menu bar 1` с локализованными именами;
- всех `menu item` каждого меню с их `name`, `enabled`, `value of attribute "AXIdentifier"` (если есть);
- всех `window` процесса с их именами и role-ами;
- всего `entire contents` главного окна (с ограничением по размеру).

Цель — понять, как **реально** называется пункт «Экспорт» в этой версии GoPro Player и есть ли альтернативные пути запустить экспорт (например, кнопка прямо в окне клипа).

Проинструктируй пользователя запустить:
```bash
osacompile -o "GoPro Menu Dump.app" scripts/gopro_dump_menu.applescript
xattr -dr com.apple.quarantine "GoPro Menu Dump.app"
```
открыть .app, дать ему права в Accessibility, открыть в GoPro Player один `.360` файл, **дождаться полной загрузки**, потом запустить `GoPro Menu Dump.app`, а потом прислать содержимое `/tmp/gopro_menu_dump.txt`.

### 2. Проверка через UI Browser / Accessibility Inspector

В качестве альтернативы можно попросить пользователя открыть **Accessibility Inspector** (входит в Xcode) и навести на меню «Экспорт…» — он покажет точные значения `AXTitle`, `AXIdentifier`, `AXEnabled`. Если у пользователя нет Xcode, прислать скриншот меню `Файл` развёрнутого в GoPro Player.

### 3. Расширить триггер экспорта

После того как известны реальные подписи и/или identifier'ы:

- Расширить массив `{"Экспорт…", "Экспорт...", "Export…", "Export..."}` в `triggerExport`/`exportMenuEnabled`/`waitForExportEnabled` на найденные варианты.
- Если у пункта стабильный `AXIdentifier`, переписать выбор пункта через `menu item 1 of menu "Файл" of menu bar 1 whose value of attribute "AXIdentifier" is "..."`.
- Если в окне клипа есть кнопка «Экспорт» — добавить fallback: попытаться кликнуть её через `click button … of window 1`.

### 4. Альтернатива: shortcut с альтернативной клавишей

Проверить через UI Browser, какой shortcut реально привязан к экспорту в GoPro Player в русской локали. На английской это `⌘E`, в локализованной может быть другой. После уточнения — поправить fallback `keystroke "e" using {command down}` в `triggerExport`.

### 5. Опциональная стабилизация

- На сетевом томе при первом открытии `.360` GoPro Player может «думать» долго. Добавить ожидание исчезновения индикатора прогресса/загрузки (если он отдельный UI-элемент) перед `waitForExportEnabled`.
- Если индексация просто не идёт (что бывает с битыми `.LRV`-сайдкарами или отсутствующим `.THM`), детектить это: если за `kExportEnabledTimeout * 2` пункт не активен, считать файл проблемным, **не удалять**, добавить в `failed` и идти к следующему.

## Известные сюрпризы AppleScript, на которые я уже наступил

Не повторяй (я их уже починил, но напоминаю как контекст):
- Двухбуквенные итераторы в `repeat with X in list` над AX-элементами иногда роняют парсер с `(-2741)` — используй `contents of itemRef` и трёхбуквенные имена (`txtRef`, `sldRef`).
- `result`, `value`, `items`, `info` — зарезервированные слова, нельзя как имена локальных переменных/параметров.
- При двойном клике .app в `on run argv` приходит `missing value`, а не `{}`. `count of missing value` = `-1708`. Нормализатор `normalizeList()` уже добавлен.
- `osascript` (бинарь) и Terminal — разные субъекты Accessibility. Для CLI-запуска нужно дать Accessibility именно `/usr/bin/osascript`. Для .app — самому .app.
- На не-APFS томах macOS создаёт AppleDouble-«дубли» `._FILE.360` — фильтруй через `find ... -not -name '._*'`.
